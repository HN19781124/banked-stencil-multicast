# Git／リリース手順

## 1. Repository separation

完成済みの原開示は [HN19781124/banked-stencil-multicast](https://github.com/HN19781124/banked-stencil-multicast) に固定する。本repositoryは周辺検証・製品化・製造引渡し用の別repositoryとして公開し、原repositoryのhistoryを書き換えない。

推奨repository名: `banked-stencil-multicast-manufacturing`

## 2. Branch / tag

- default branch: `main`
- feature: `feature/<scope>`
- release preparation: `release/vX.Y.Z`
- tag: signed annotated `vX.Y.Z`
- manufacturing baseline tag: `mb/<baseline-id>/<run-id>`

`main`へのmerge条件:

- required CI PASS
- requirement/document test PASS
- review approval
- no unresolved high-severity secret/license finding
- generated binary/build outputをcommitしない

## 3. Commit sequence for initial publication

1. import completed scheduler/reference/licenses
2. add peripheral/Halo/cross-row validation
3. add SRAM/multicast integrated RTL simulation
4. add manufacturing baseline and handoff dossier
5. add CI/release metadata

各commitはbuildable/testableにする。author、date、commit hashをrelease manifestへ保持する。

## 4. CI

`.github/workflows/verify.yml`はclean checkoutで次を実行する。

```shell
python tools/verify.py --bootstrap --require-rtl
```

CI artifact:

- `build/verification-report.json`
- simulation logs（失敗時を含む）
- future coverage/formal/physical summary

PDKを含むjobはPDK licenseと容量を確認し、public CIへ再配布不可のdataをuploadしない。

## 5. Release contents

- source archive generated by GitHub
- README、license、documentation license
- manufacturing baseline JSON
- verification report
- requirement/traceability/risk/sign-off documents
- third-party NOTICE/SBOM
- SHA-256 manifest
- physical artifacts only when corresponding sign-off gate PASS

release noteは「verified」と「planned」を分離し、pre-layout性能をsilicon実測として記載しない。

## 6. Publication procedure

```shell
git status --short
python tools/verify.py --bootstrap --require-rtl
git switch -c main
git add --all
git commit -m "Prepare manufacturing-reference design package"
git remote add origin <new-repository-url>
git push -u origin main
git tag -s v0.2.0 -m "Manufacturing-reference documentation baseline"
git push origin v0.2.0
```

remote URLは新repository作成後に設定する。原repositoryの`origin`を流用しない。

## 7. Change control after baseline

RTL、constraint、PDK、macro、tool、FP rule、interface、clock targetの変更はECOとして記録し、影響する要求とgateを再実行する。layout freeze後の変更はbaseline IDを更新し、旧runを削除せずarchiveする。
